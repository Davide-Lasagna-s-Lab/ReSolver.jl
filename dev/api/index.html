API

Unknowns and system

ReSolver.Orbit — Type
Orbit(a, p)

Unknowns of the search. These are the space-time field a, in any discretisation, and the parameter vector p = [log ω, c₁, c₂, …], the logarithm of the frequency ω = 2π/T followed by one drift speed per drift direction of the System. The frequency is searched through its logarithm, which keeps it positive and makes a step a relative change of ω. frequency returns ω. Orbits broadcast like vectors, and dot adds the inner product of the fields to that of the parameters. The parameters are stored in the real type of the field, Float32 for a single-precision field.

x = Orbit(a, [log(2π/T), c])
source
ReSolver.frequency — Function
frequency(x::Orbit) -> ω

The frequency ω = 2π/T of the orbit, from its logarithm x.p[1].

ReSolver.System — Type
System(nl, lin, adj, dds!, x::Orbit; linearise!, ddi=(), B=I, project=identity)
System(nl, lin, dds!, x::Orbit; linearise!, ddi=(), B=I, project=identity)
System(nl, dds!, x::Orbit; difference=:forward, ddi=(), B=I, project=identity)

The system with nonlinear operator nl and rescaled-time derivative dds!, on orbits shaped like x. The three constructors differ in the operators given.

  • With the linearised and adjoint operators lin and adj, and the function linearise!(op, a) that sets the linearisation point of lin or adj, the system serves both NewtonHookstep and LBFGS.
  • Without the adjoint operator, it serves the hookstep only, since only L-BFGS applies the adjoint. L-BFGS throws an ArgumentError.
  • With the nonlinear operator alone, the system is Jacobian-free. The hookstep applies the linearised operator by finite differences of nl, with the step ε = δ (1 + ‖a‖) / ‖b‖. difference=:forward takes L b ≈ (N(a + ε b) - N(a)) / ε, one evaluation of nl per Jacobian action, with δ the square root of the machine precision of the fields. difference=:central takes L b ≈ (N(a + ε b) - N(a - ε b)) / 2ε, of second order and two evaluations per action, with δ the cube root. The residual is exact, so the converged orbit is as accurate as with the linearised operator. L-BFGS throws an ArgumentError.

For the Kuramoto–Sivashinsky example,

System(KSNonlinear(g), KSLinearised(g), KSLinearised(g; adjoint=true), dds!, x;
       linearise!, ddi=(ddx!,))                                  # both methods
System(KSNonlinear(g), KSLinearised(g), dds!, x; linearise!, ddi=(ddx!,))   # hookstep
System(KSNonlinear(g), dds!, x; ddi=(ddx!,))                     # hookstep, Jacobian-free
System(KSNonlinear(g), dds!, x; difference=:central, ddi=(ddx!,)) # second order

ddi is a tuple of functions dd!(out, a) -> out, the derivatives along the directions of translational symmetry in which the orbit drifts with an unknown speed, one per drift speed in x.p. The default () searches for periodic orbits. Leave out the directions in which a symmetry of the problem forbids drifting.

B is the preconditioner, an invertible operator on orbits for which precondition! and precondition_adjoint! are defined. It is the identity I by default.

project(a) -> a restricts the search to a subspace of fields that the residual and the Jacobian map into itself. It projects the field a in place, orthogonally, onto the subspace. Examples are the fields fixed by a symmetry of the problem, and the fields of zero mean when the equation of the mean is void, as for Kuramoto–Sivashinsky. The projection is applied to the initial orbit, and to every residual, gradient, Jacobian action and application of the preconditioner, so that the search stays in the subspace despite rounding errors. The default identity does nothing.

Methods

ReSolver.solve! — Function
solve!(x::Orbit, F::System, method) -> x

Search for an orbit of the system F, starting from x and overwriting it with the result. method is an LBFGS object, which minimises ½‖r‖² and is robust far from a solution, or a NewtonHookstep object, which solves r = 0 and converges fast close to one. Both hold their own options. A typical search runs L-BFGS first and refines with the hookstep.

solve!(x, F, LBFGS(maxiter=300))
solve!(x, F, NewtonHookstep(krylov_dim=150))
source
ReSolver.LBFGS — Type
LBFGS(; memory=10, maxiter=100, tol=1e-10, verbose=true, io=stdout, callback=info -> false)

L-BFGS minimisation of ½‖r‖², for solve!. Robust far from a solution. The gradient comes from the adjoint operator, so the system must be built with it.

The direction comes from the last memory curvature pairs, in the metric of the preconditioner of the system, and the step from a backtracking Armijo line search. With memory=0 the method is steepest descent in the metric of the preconditioner, scaled by the newest step (Barzilai–Borwein).

  • The search stops when ‖r‖ < tol, after maxiter iterations, or when callback(info) returns true. The callback is called at the start and after every iteration. info is a named tuple with the iteration iter, the orbit x, the residual norm res and the cumulative evaluations of the system. Its fields krylov and step are empty here, and trust holds NaN and 0. A Trace records them.
  • verbose=true prints one line per iteration to io.
source
ReSolver.NewtonHookstep — Type
NewtonHookstep(; krylov_dim=50, krylov_tol=1e-3, Δ=1e-2, Δmax=1, eta=1e-3, maxiter=20,
                 tol=1e-10, flexible=false, relinearise=true, recycle=0, trust=:ratio,
                 metric=:krylov, verbose=true, io=stdout, callback=info -> false)

Newton–Krylov hookstep solution of r = 0, for solve!. Fast near a solution.

Each Newton iteration builds a Krylov space of the right-preconditioned Jacobian, up to dimension krylov_dim or until the GMRES solution of the Newton system has a residual below krylov_tol times ‖r‖. The step is the hookstep in that space, the minimiser of the linear model within the trust region. The radius starts at Δ and never exceeds Δmax. A step is accepted when the actual reduction of ½‖r‖² is at least eta times the predicted one.

  • flexible=true keeps the preconditioned Arnoldi vectors and forms the step from them (flexible GMRES). Use it with a preconditioner that changes between Arnoldi steps, e.g. one applied by an inner iterative solver. It doubles the memory of the Krylov space.
  • relinearise=true rebuilds the preconditioner about the current orbit at the start of every Newton iteration, by relinearise!, which does nothing for a preconditioner that defines no method.
  • The search stops when ‖r‖ < tol, after maxiter iterations, or when callback(info) returns true. The callback is called at the start and after every iteration. info is a named tuple with the iteration iter, the orbit x, the residual norm res, the cumulative evaluations of the system, krylov, the relative residual of the GMRES solution after each Arnoldi step of the iteration, step, "newton" or "hook", the kind of the accepted step, and trust, a named tuple with the trust-region radius radius with which the accepted step was computed, its length length in the metric of the preconditioner, the ratio ratio of the actual to the predicted reduction of ½‖r‖², the number rejected of trial steps rejected before it, and trials, the radius and the ratio of each of them. A Trace records them.
  • recycle=k carries k directions of the step from one Newton system to the next: the right singular vectors of the smallest singular values of the restricted Jacobian of the last system, the slow directions that GMRES would otherwise find again. Each system then applies the Jacobian to them once, k more actions, and builds its Krylov space orthogonal to their images. The default 0 recycles nothing.
  • trust=:ratio updates the radius from the ratio ρ of each trial: by 4 down below 1/4, by 2 up above 3/4 on the boundary. trust=:scan tries the hookstep at the radii Δ p, p = 2^(j/2) for j = -6, …, 4, in the same Krylov space, accepts the trial of smallest residual among those with ρ > eta, and starts the next iteration from the length of its step. Each trial costs one residual. trials then holds every trial but the accepted one, and rejected those with ρ ≤ eta.
  • metric=:krylov measures a step by its coordinates in the Krylov space, ‖B δx‖ for a fixed preconditioner. metric=:operator measures it by ‖M δx‖, with M applied by metric! of the preconditioner, for a preconditioner whose inverse is not one fixed operator, e.g. one that solves some directions exactly. It needs flexible=true, and neither recycling nor a free parameter, and keeps the vectors M B⁻¹ qⱼ, one more field per Arnoldi step.
  • parameter=(; derivative!, update!, value) leaves a parameter σ of the residual free, an unknown of the Newton step with no extra equation. derivative!(out, x) writes ∂r/∂σ at x into the orbit out, with zero phase conditions, update!(δσ) changes the parameter of the system by δσ, and value() returns it. The Newton system then has one more unknown than equations, and its solutions near an orbit form a branch along σ: the hookstep takes the correction of least norm within its Krylov space, whose solutions converge to a point of the branch near the guess. The column ∂r/∂σ enters the space as a recycled direction would, with no Jacobian action, and the trust region measures the change of σ by the change of the residual it produces. info.parameter holds the value. The default nothing keeps the parameter fixed. Not with recycle > 0.
  • verbose=true prints one line per iteration to io.

Tracing

ReSolver.Trace — Type
Trace()

History of a search, filled when passed as callback to LBFGS or NewtonHookstep. At the start and after every iteration it records the following fields.

  • iter, the iteration number of the method.
  • res, the residual norm ‖r‖.
  • p, the parameters [log ω, c₁, …].
  • time, the seconds elapsed since the first record.
  • evaluations, the cumulative numbers of residuals, gradients, Jacobian actions, adjoint Jacobian actions and preconditioner applications of the system.
  • krylov, for the hookstep, the relative residual of the linear model after each Arnoldi step of the iteration. It is empty for L-BFGS and at the start.
  • step, for the hookstep, "newton" if the accepted step is the full Newton step, inside the trust region, or "hook" if it lies on its boundary. It is empty for L-BFGS and at the start.
  • radius, steplength, ratio and rejected, for the hookstep. These are the trust-region radius with which the accepted step was computed (at the start, the initial radius), the length of that step in the metric of the preconditioner, the ratio of the actual to the predicted reduction of ½‖r‖², and the number of trial steps rejected before it. They are NaN and 0 for L-BFGS.
  • trials, for the hookstep, the radius and the ratio of each trial step rejected before the accepted one, in order. Each rejection divides the radius by 4. It is empty for L-BFGS.

The same trace can follow several calls to solve!, such as L-BFGS and then the hookstep. The iteration numbers restart at zero with each call.

trace = Trace()
solve!(x, F, LBFGS(callback=trace))
solve!(x, F, NewtonHookstep(callback=trace))

trace.res # residual norms, in order

Preconditioners

ReSolver.precondition! — Function
precondition!(out::Orbit, B, p::Orbit) -> out

Apply the inverse of the preconditioner B to the orbit p, out = B⁻¹ p. Extend it, together with precondition_adjoint!, for each preconditioner type.

source
ReSolver.precondition_adjoint! — Function
precondition_adjoint!(out::Orbit, B, p::Orbit) -> out

Apply the adjoint of the inverse of the preconditioner B to the orbit p, out = B⁻⁺ p, in the inner product of the orbits. For a self-adjoint B it is precondition!.

source
ReSolver.relinearise! — Function
relinearise!(B, x::Orbit) -> B

Rebuild the preconditioner B in place about the orbit x, its frequency, drift speeds and field. NewtonHookstep calls it at the start of every Newton iteration with the current orbit, unless relinearise=false. L-BFGS never calls it. The default does nothing, so a preconditioner that does not depend on the orbit, or the identity, needs no method.

Residual, gradient and Jacobian

These functions are used by the methods and are not exported. They are useful to check a system.

ReSolver.residual! — Function
residual!(r::Orbit, F::System, x::Orbit) -> r

The augmented residual at x. Its field is r.a = ω ∂s a - Σᵢ cᵢ ∂ᵢ a - N(a). Its parameters r.p are the phase conditions, which vanish at the current point, so they are zero. Minus r is the right-hand side of the Newton system.

source
ReSolver.objective — Function
objective(F::System, x::Orbit) -> R

R = ½‖r‖². The residual is left in F.residual.

source
ReSolver.gradient! — Function
gradient!(g::Orbit, F::System, x::Orbit) -> R

Write the gradient of R = ½‖r‖² into g and return R. Moves the linearisation point of the operators to x.

source
ReSolver.jacobian! — Function
jacobian!(out::Orbit, F::System, x::Orbit, δx::Orbit) -> out

The Jacobian of the residual at x, with the phase conditions as extra rows, applied to δx. Assumes the linearisation point was set to x with F.linearise!(F.lin, x.a).

source
ReSolver.jacobian_adjoint! — Function
jacobian_adjoint!(out::Orbit, F::System, x::Orbit, w::Orbit) -> out

The adjoint of jacobian! in the inner product of the orbits, applied to w. With w = (w_a, [w_s, w₁, …]), the field and the multipliers of the phase conditions,

out.a = -ω ∂s w_a + Σᵢ cᵢ ∂ᵢ w_a - L⁺ w_a + w_s ∂s a + Σᵢ wᵢ ∂ᵢ a
out.p = [ω ⟨∂s a, w_a⟩, -⟨∂₁ a, w_a⟩, …]

so that ⟨w, 𝒥 v⟩ = ⟨𝒥⁺ w, v⟩ for all orbits v. Assumes the linearisation point of the adjoint operator was set to x with F.linearise!(F.adj, x.a). Needed by Krylov solvers of the least-squares problem min ‖𝒥 δx + r‖, such as LSQR. The gradient of R = ½‖r‖² is 𝒥⁺ (r, 0).
